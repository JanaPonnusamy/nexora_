9. NewLicenseKey PROCESSING PATH
   - DB table dbo.Mx_LicenseUpdateTrn stores NewLicenseKey (14 groups, e.g.
     4041-7B95-...-1D87) as an AUDIT TRAIL only (prior phase established this).
   - The OPERATIVE key returned by the live API is DIFFERENT and longer -- a
     32-group hex-grouped blob (64 bytes):
       88D3-587E-0670-A8FF-40A0-C8A1-A94C-D330-102F-009C-E000-5B00-32FE-585C-
       0000-0000-0000-C000-0000-0200-0000-0000-0000-0000-2602-0000-3B94-1400-
       0000-0000-0000-0000
   - Structure (high level, from format only -- decoder is server-side):
       * Fixed-length, uppercase hex, grouped in 4-hex (2-byte) segments.
       * Server-side LicenseInformationController.PageLoad decodes it into typed
         fields (ProductVariant, MaxUser, ActiveUser?, LicDevice, PackageValidity,
         AppMode, per-module AllowedLimit). The many 0000 groups suggest reserved
         / per-module capacity slots within a custom binary layout.
   - Encoding vs crypto: CANNOT be determined remotely. Whether the blob is plain
     packed-binary, checksummed, encrypted, keyed-hash/MAC, or digitally signed is
     decided entirely inside the compiled server assembly (item 5), which is not
     reachable from this machine. NOT DETERMINED. (No attempt was or will be made
     to reproduce/forge a key.)
