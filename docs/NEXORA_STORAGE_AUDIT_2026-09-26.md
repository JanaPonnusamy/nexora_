## Executive summary

The workspace is large mainly because it contains runtime data, database/export artifacts, build outputs, and local dependency installations alongside source code.

- `backend` uses **5.994 GiB (53.5%)**.
- `release` uses **1.920 GiB (17.1%)** for one installer.
- `ho_setup` uses **0.899 GiB (8.0%)**, almost entirely a SQL Server backup payload.
- `.git` uses **0.833 GiB (7.4%)**.
- `frontend` uses **0.593 GiB (5.3%)**, mainly `node_modules`.
- About **1.94 GiB** can be reclaimed from clearly regenerable dependency/build folders.
- Stopping the backend and removing/rotating old logs raises the low-risk reclaim estimate to about **2.32 GiB**.
- Another **3.08 GiB** consists of installer/build artifacts that can be removed only after confirming that retained copies exist or that a successful rebuild is possible.
- Do not blanket-delete the WhatsApp profile, database/cache database, SQL exports, or `.git` folder.

## Git repository observations

- Git reports 629.55 MiB in pack files, 208.68 MiB in loose objects, and 12.36 MiB of temporary garbage.
- A Git maintenance operation may reclaim at least the reported garbage, but do it only when no Git process is running and after ensuring the repository has a valid remote/backup.
- Never manually delete `.git/objects` or pack files.
- The working tree already contains many deletions under the tracked `.buildvenv` path. This audit did not create or modify those deletions.
- `.builddeps` is tracked by Git, unlike the other dependency/cache directories. Removing it would create source-control deletions and is not included in the safe reclaim total.

## Recommended cleanup order

1. Stop frontend, backend, Playwright, and Flutter development processes.
2. Remove only the green-tier dependency/build folders. Reinstall them when required.
3. Stop the backend service, archive any needed recent logs, then clear or rotate `backend/logs`.
4. Move old installers from `release`, `dist`, and `backend/updates` to an artifact store before deleting local copies.
5. Resolve the oddly named `ho_setup/assets/Nexora_platform` backup and keep one verified protected copy.
6. Review the SQL/RAR exports under a formal backup and PII-retention policy.
7. Treat WhatsApp profile cleanup as an application maintenance task; do not delete the whole profile merely to free space.
8. Add log rotation and artifact retention limits so the workspace does not regrow unchecked.
