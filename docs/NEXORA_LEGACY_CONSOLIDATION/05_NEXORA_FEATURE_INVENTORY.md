## C. Cross-cutting observations relevant to the consolidation decision

1. **Procurement already depends on Legacy Order for sync + branch-stock
   reads** (doc 04 §6: `distribution_service`, `distribution_providers`,
   `reports/repository`, `abnormal_sales_repository` all import from
   `legacy_order`). Any plan that "retires" Procurement wholesale needs to
   either keep these specific files alive or re-home their logic into Legacy
   Order first — they are not Procurement-specific, they are infrastructure
   Procurement borrowed.

2. **Two unresolved duplicate-ownership pairs surfaced in this pass** that
   should be settled before reuse, not assumed resolved:
   - Supplier Stock harvesting/analysis: `procurement/supplier_stock_*` vs
     `legacy_order/supplier_stock_harvest.py` + `supplier_portal.py`.
   - Non-moving stock: `nonmoving_report/*` vs `nonmoving_analysis/*` (both
     mounted, not diffed against each other this pass).

3. **Two different "how much should the warehouse buy" answers exist**:
   Product Intelligence's cross-store VPL union (table A) vs NMW Sales
   Report's despatch-bill-based demand signal (table B) vs the user's memory
   hint "NMW warehouse order demand basis = retail despatch." These were not
   cross-validated against each other in this pass — flagging as a decision
   point, not resolving it here.

4. **The single clearest, lowest-risk reuse candidate** is
   `legacy_order_parity.py` (doc 04 §5) — already proven, already the
   default, already unit-testable, already produces the exact row shape the
   rest of the pipeline (working items, PM grid, assignment, export) expects.
   Everything built on top of the VPL (tables A's Cycle/Refresh orchestration,
   Working Items, Pending, GRN Reconciliation) is reusable in proportion to
   how much of that downstream plumbing the owner also wants to keep — they
   were not designed to be separable from the VPL/Refresh model.

5. **Feature-gated / not-fully-wired code should not be assumed production
   behavior**: VPL History (`PROCUREMENT_VPL_HISTORY`), Refresh Idempotency
   (`PROCUREMENT_REFRESH_IDEMPOTENCY`), and the GRN store-sync trigger
   (`reconciliation_service._trigger_store_sync`, a no-op stub) are all real
   code paths that do **not** currently run in the default configuration —
   see doc 04 §3, §6, §13 for each.
